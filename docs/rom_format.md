# EmbFont16 ROM binary format

Format version: **2.0** (`0x00020000`)

This document describes the fixed-size ROM images produced by
`tools/bin/font_builder` (`output/EmbFont16*.bin`). The layout is shared by
all output sets; only the embedded glyphs and license text differ.

The format is little-endian. The image is always 4 MiB (`0x400000` bytes).

## Memory map

| Range | Size | Contents |
|---|---:|---|
| `0x000000`–`0x0000FF` | 256 B | Header (112 B used, rest zero) |
| `0x000100`–`0x001FFF` | 7,936 B | Embedded license text (NUL-terminated) |
| `0x002000`–`0x003FFF` | 8,192 B | Block table (1,024 entries × 8 B) |
| `0x004000`–`0x007FFF` | 16,384 B | Reserved area (font names at `0x004000`) |
| `0x008000`–`0x3FFFFF` | 4,161,536 B | Glyph data area and padding |

The fixed offsets are defined in `src/include/embfont16_common.h`. A reader
may use those constants directly; it does not need to parse the header first.

## Header (`0x000000`–`0x0000FF`)

The header is the packed `FontHeader` structure (112 bytes). Bytes
`0x70`–`0xFF` are zero.

| Offset | Type | Field | Value / meaning |
|---:|---|---|---|
| `0x00` | `u32` | `magic` | `0x544E4F46` (`"FONT"` in little-endian) |
| `0x04` | `u32` | `version` | `0x00020000` for format 2.0 |
| `0x08` | `u32` | `char_count` | Number of existing glyph records |
| `0x0C` | `u32` | `reserved1` | Zero |
| `0x10` | `u8[64]` | `font_name` | Reserved; currently zero |
| `0x50` | `u32` | `credits_offset` | `0x00000100` |
| `0x54` | `u32` | `credits_size` | `0x00001F00` (7,936 B) |
| `0x58` | `u32` | `table_offset` | `0x00002000` |
| `0x5C` | `u32` | `table_size` | `0x00002000` (8,192 B) |
| `0x60` | `u32` | `reserved_area_offset` | `0x00004000` |
| `0x64` | `u32` | `reserved_area_size` | `0x00004000` (16,384 B) |
| `0x68` | `u32` | `glyph_area_offset` | `0x00008000` |
| `0x6C` | `u32` | `glyph_area_size` | Used glyph data bytes (multiple of 9,216) |

A valid image has `magic == 0x544E4F46`. Readers should check `version`'s
major part when they depend on a specific layout.

## License area (`0x000100`–`0x001FFF`)

The builder copies the file supplied with `-l <path>` into this area. The text
is stored as raw bytes, followed by a NUL terminator, and the rest of the area
is zero-filled. At most 7,935 bytes of text are stored; longer files are
truncated.

If no license is supplied, the whole area is zero.

| Output | Embedded text |
|---|---|
| `EmbFont16.bin` | `assets/licenses/CREDITS` (X11-style font license) |
| `EmbFont16JP.bin` | None |
| `EmbFont16Uni.bin` | `assets/licenses/LICENSE_UNIFONT` (SIL OFL 1.1) |
| `EmbFont16Ank.bin` | None |

The same text is copied to `output/CREDITS.txt` or
`output/LICENSE_UNIFONT.txt` during the build.

## Block table (`0x002000`–`0x003FFF`)

The code space `U+00000`–`U+3FFFF` is divided into 1,024 blocks of 256 code
points. Block `B` covers `B * 256` through `B * 256 + 255`, where
`B = cp >> 8`. All 1,024 entries are present; entry `B` starts at
`0x002000 + B * 8`.

Each entry is the packed `BlockTableEntry` structure:

| Offset | Type | Field | Meaning |
|---:|---|---|---|
| `0x00` | `u32` | `glyph_offset` | Offset of the block data, relative to `glyph_area_offset`; `0xFFFFFFFF` means the block is absent |
| `0x04` | `u16` | `block_id` | Block index (0–1023) |
| `0x06` | `u8` | `line_value` | Low nibble: first used row. High nibble: `line_count - 1` |
| `0x07` | `u8` | `reserved` | Zero |

`line_value` is shared by every glyph in the block:

- `start_line = line_value & 0x0F`
- `line_count = ((line_value & 0xF0) >> 4) + 1`

For an absent block, `glyph_offset` is `0xFFFFFFFF` and `line_value` is zero.
For a block that exists but contains only blank glyphs, `start_line` is 0 and
`line_count` is 1.

Present blocks are stored in ascending block order, tightly packed. The first
present block has offset 0, the next 9,216, and so on. Readers should still use
`glyph_offset` rather than relying on this ordering.

## Reserved area (`0x004000`–`0x007FFF`)

The first 1,024 bytes hold up to 16 font-name entries of 64 bytes each:

```c
#define FONT_NAME_AREA_OFFSET  0x004000
#define FONT_NAME_ENTRY_SIZE   64
#define FONT_NAME_MAX_ENTRIES  16
```

Each entry is a NUL-terminated name. The entry index is the `font_id` stored in
glyph records. Unused entries are zero. The remainder of the reserved area is
zero.

The names are display names generated by `gen_map` from the source
identifiers (for example, `milkjf 8x16` or `GNU Unifont JP`).
`embfont16_get_font_name_ptr()` returns a pointer to a static buffer containing
the requested name; `embfont16_get_font_name()` copies the name into a
caller-supplied buffer.

## Glyph data area (`0x008000`–)

A present block occupies 9,216 bytes: 256 glyph records of 36 bytes each, in
code-point order. Missing code points inside a present block are stored as
all-zero records.

The maximum number of blocks is
`floor((0x400000 - 0x8000) / 9216) = 451`.

### Glyph record (36 bytes)

| Offset | Size | Field | Meaning |
|---:|---:|---|---|
| `+0` | 1 | `exists` | 1 = glyph exists; 0 = missing |
| `+1` | 1 | `half` | 1 = 8-pixel-wide glyph; 0 = 16-pixel-wide glyph |
| `+2` | 1 | `font_id` | Source font index (0–15) |
| `+3` | 1 | `reserved` | Zero |
| `+4` | 32 | `data` | Packed bitmap rows, `line_count * 2` bytes used |

### Bitmap packing

- One row is always two bytes (16 bits).
- Byte 0 is the left 8 pixels; byte 1 is the right 8 pixels.
- Within each byte, bit 7 is the leftmost pixel. 1 = foreground, 0 = background.
- For half-width glyphs, only byte 0 is used and byte 1 is zero.
- Row `k` of `data` corresponds to cell row `start_line + k`.
- Bytes not covered by `line_count` rows are zero.

## Reading a glyph

Given a code point `cp <= 0x3FFFF`:

1. Read the 8-byte block entry at
   `table_offset + ((cp >> 8) * 8)`.
2. If `glyph_offset == 0xFFFFFFFF`, the glyph is absent.
3. Read the 4-byte record header at
   `glyph_area_offset + glyph_offset + ((cp & 0xFF) * 36)`.
4. If `exists == 0`, the glyph is absent.
5. Read `line_count * 2` bitmap bytes starting at record offset `+4`.

The runtime in `src/embfont16.c` performs these reads through the single
`hal_embfont16_read()` HAL function.

## Version history

| Version | Layout |
|---|---|
| `0x00010000` | Initial layout: license area `0x000100`–`0x000FFF`, block table at `0x001000` |
| `0x00020000` | Current: 7,936-byte license area, block table at `0x002000`, reserved area at `0x004000` |

The current layout was introduced to embed the complete SIL OFL 1.1 text in
`EmbFont16Uni.bin` without truncation.
